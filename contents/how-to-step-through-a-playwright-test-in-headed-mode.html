How to Step Through a Playwright Test in Headed Mode

Think of a Playwright test like a robot clicking through your app.

By default the robot works with the lights off. That is headless mode: no browser window, just a pass or fail at the end. Fast, but when a test fails you only see the aftermath.

Sometimes you want to turn the lights on and watch the robot, one move at a time.

Playwright gives you three ways to do that:

  1. --headed → watch the robot work at full speed
  2. --debug → make the robot wait for you before every move
  3. --ui → rewind and replay every move afterwards

1. --headed = “Turn the lights on”

npx playwright test tests/checkout.spec.ts --headed

A real browser window opens and the test runs in it. You see every click and every page load.

“But it finishes in two seconds. How am I supposed to follow it?”

You can't, really. --headed shows you that something happened, not why. For that you need to slow the robot down.

2. --debug = “Wait for me before every move”

npx playwright test tests/checkout.spec.ts --debug

This opens two windows:

  • The browser, paused before the first step.
  • The Playwright Inspector, showing your test code with the current line highlighted.

Now you drive:

  • Step over (F10) → run the next line, then pause again
  • Resume (F8) → run until the next pause or the end

On each step, the Inspector highlights the element the line is about to act on, and shows a log of what Playwright did: which locator it waited for, how long it waited, what it clicked.

✅ This is the best way to find out why a locator doesn't match.

“My test has 40 lines. I only care about line 35.”

Stepping through 34 lines to get there is painful. There is a shortcut.

3. page.pause() = “Stop here”

Put a pause exactly where you want to start looking:

test('checkout', async ({ page }) => {
  await page.goto('/cart');
  await page.getByRole('button', { name: 'Checkout' }).click();

  await page.pause(); // ← the robot stops here

  await page.getByLabel('Card number').fill('4242 4242 4242 4242');
});

Then run with --headed, not --debug:

npx playwright test tests/checkout.spec.ts --headed

The test runs at full speed until it reaches page.pause(), then opens the Inspector. From there you step as before.

Remember to delete the page.pause() before you commit.

4. --ui = “Rewind and replay”

npx playwright test tests/checkout.spec.ts --ui

UI mode is different. Instead of pausing the test, it records it. You get:

  • A timeline of every action.
  • A snapshot of the page before and after each action. Click one to inspect it.
  • Every network request the page made, with its response.
  • Console logs and errors, lined up with the step that caused them.
“When would I pick this over --debug?”

When the problem is about timing, such as a request that comes back late, or a button that is disabled for half a second. Pausing the test changes the timing and can hide the bug. UI mode lets the test run at real speed, then lets you go back and look.

5. From VS Code

If you have the Playwright Test for VS Code extension installed:

  1. Set a normal breakpoint in your spec file.
  2. In the Testing sidebar, tick Show browser.
  3. Right-click the green run icon next to the test → Debug Test.

Now you get the VS Code debugger: hover over variables, inspect locator objects, use the debug console, all while the browser window sits open next to it.

One Trap: Which Server Is the Test Hitting?

Most Playwright configs read the app's address from somewhere like this:

// playwright.config.ts
const baseURL = process.env.PLAYWRIGHT_BASE_URL ?? 'http://localhost:5173';

If you have two copies of your app running, say your main branch on 5173 and a fix branch on 5174, the test will happily run against the wrong one. You'll step through it carefully and wonder why your fix isn't working.

Point it at the right server before running:

# macOS / Linux
PLAYWRIGHT_BASE_URL=http://localhost:5174 npx playwright test tests/checkout.spec.ts --debug

# Windows PowerShell
$env:PLAYWRIGHT_BASE_URL = 'http://localhost:5174'
npx playwright test tests/checkout.spec.ts --debug

Note that the VS Code extension doesn't see variables you set in your terminal. Put the value in an .env file your config loads instead.

Simple Real-Life Analogy

Imagine watching a football match.

  • Headless → you only read the final score.
  • --headed → you watch the match live.
  • --debug → the referee stops play after every pass and waits for your signal.
  • page.pause() → you skip straight to the 80th minute.
  • --ui → the full replay, with every angle, after the match.

Summary

  • --headed shows the browser, at full speed.
  • --debug pauses before every step and opens the Inspector.
  • page.pause() + --headed pauses only where you want.
  • --ui records everything so you can look back, best for timing bugs.
  • Always check which server baseURL points at.
