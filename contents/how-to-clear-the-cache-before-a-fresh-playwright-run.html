How to Clear the Cache Before a Fresh Playwright Run

A test keeps failing, and you want to rule out leftovers from earlier runs. You want a fresh login, fresh results and a fresh build, nothing carried over.

“Where does Playwright keep things between runs, and which of them should I delete?”

There are five places. Here they are, one at a time.

1. Test results

Every failure leaves a folder in test-results/ with a screenshot, a trace and an error-context.md. Playwright empties this folder at the start of each run, so you rarely need to delete it yourself. The exception is when you want old failures gone before you start. 

rm -rf test-results

One file in there matters: test-results/.last-run.json. It lists the tests that failed last time, and --last-failed reads it: 

yarn e2e --last-failed

Delete test-results/ and --last-failed has nothing to go on, so it runs every test.

2. The saved login

Most suites log in once and save the session to a file. The config then hands that file to every test: 

// playwright.config.ts
use: {
  storageState: 'e2e/.auth/user.json',
}

That file holds cookies and localStorage: the auth tokens and anything else the app remembers, such as the last workspace or place you picked.

“If I log in as someone else, why do the tests still act like the old account?”

Your global setup may skip the login when the file already exists. If it does, the tests keep using the old session. Delete the file to force a new login: 

rm -rf e2e/.auth

This file is a live session. Keep it in .gitignore, and don't paste it anywhere.

3. Playwright's own cache

Before it runs your specs, Playwright compiles the TypeScript and caches the output. If a test seems to run old code after you edited it, clear that cache: 

npx playwright clear-cache

This doesn't touch your results, your login or the browsers.

4. The app build

If the config starts the app for you, check what webServer actually runs: 

webServer: {
  command: 'yarn build && yarn preview --port 4173 --strictPort',
  url: 'http://localhost:4173',
  reuseExistingServer: false,
}

This one builds every time, so dist/ is always fresh. Look out for two things:

  • A flag that skips the build. If the config skips yarn build when some environment variable is set, the tests run against whatever dist/ already holds. Unset that variable for a fresh run.
  • reuseExistingServer: true. If anything is already listening on that port, Playwright uses it, even if it's an old build from earlier.
“Why does the run fail before a single test starts?”

With --strictPort, the preview server won't move to another port. It just stops. The usual cause is a server from an earlier run, often a Playwright UI window you forgot to close. Find what's using the port: 

# Windows
netstat -ano | findstr :4173

# macOS / Linux
lsof -i :4173

Close that window, or stop the process, and the port is free again.

5. The browsers

Browser binaries live outside your project, in a shared folder (ms-playwright). You almost never need to clear it. If a browser crashes on launch, or seems to be the wrong version, reinstall it: 

npx playwright install --force chromium

All Together

# 1. close any Playwright UI window that's still running
# 2. clear results, the saved login and the compile cache
rm -rf test-results e2e/.auth
npx playwright clear-cache

# 3. run everything: fresh build, fresh login
yarn e2e

What a Fresh Run Won't Fix

Clearing the cache only removes what's on your machine. If your tests run against a live API, the data lives on the server.

“The run was fresh. Why is the same test still failing?”

Open the failure's trace and look at the API responses: 

npx playwright show-trace test-results/<test-folder>/trace.zip

Suppose the list query comes back with total_size: 0 and the test is waiting for the first row. Then nothing is stale: the account just has no data. No amount of clearing fixes that. Either point the tests at an account that has the data, or have each test create what it needs before it starts.

Summary

  • test-results/ is emptied at the start of each run. Delete it yourself only to clear old failures or reset --last-failed.
  • Delete the storageState file to force a new login.
  • npx playwright clear-cache clears the compiled test code.
  • Make sure webServer really rebuilds, and that nothing else is holding its port.
  • Reinstall a browser with npx playwright install --force, and only if it's broken.
  • If a fresh run still fails, check the trace. The problem may be the data, not the cache.
