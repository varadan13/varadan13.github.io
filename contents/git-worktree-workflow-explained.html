Git Worktree Workflow Explained

Think of a Git repository like a house with one desk.

Normally you can only work on one branch at a time. If you are halfway through a feature and someone asks for a quick fix, you have to clear the desk first: commit half-done work, or git stash it, then switch branches.

A worktree gives the same house a second desk.

  • Same repository, same history, same commits.
  • A separate folder on disk.
  • A different branch checked out in that folder.

Here is the whole workflow at a glance:

Create
  ↓
git worktree add -b new-branch ../new-branch main
  ↓
Work + commit
  ↓
Go to main worktree
  ↓
git pull
  ↓
git merge new-branch
  ↓
git push
  ↓
git worktree remove ../new-branch
  ↓
git branch -d new-branch

Let's walk through each step.

1. Create the worktree

git worktree add -b new-branch ../new-branch main

Read it right to left:

  • main → start from the main branch
  • ../new-branch → put the new folder next to the current repo, not inside it
  • -b new-branch → create a new branch called new-branch

Your disk now looks like this:

projects/
├── my-repo/        ← main worktree, on branch main
└── new-branch/     ← new worktree, on branch new-branch
Why not just put both folders on main?

Git does not allow it. A branch can only be checked out in one worktree at a time. That is why the new worktree always gets its own branch.

2. Work and commit

cd ../new-branch
# edit files
git add .
git commit -m "Add the new feature"

Nothing special here. This folder behaves like any normal clone. The difference: your my-repo folder is untouched. You can keep it open in another editor window, run its dev server, or fix something else in it at the same time.

Commits made here are visible from every worktree immediately, because they all share the same .git data.

3. Go back to the main worktree

cd ../my-repo

The merge happens where main is checked out. That is the original folder.

4. Pull first

git pull
Why pull before merging?

While you were working, other people may have pushed to main. If you merge first and pull later, you get an extra merge commit, or a push that gets rejected. Pulling first means you merge into the latest main.

5. Merge the branch

git merge new-branch

This brings your commits into main. If there are conflicts, you fix them here, in the main worktree, like any other merge.

6. Push

git push

✅ Your work is now on the remote main.

7. Remove the worktree

git worktree remove ../new-branch

This deletes the folder and tells Git the second desk is gone.

Why not just delete the folder by hand?

You can, but Git still remembers it until you run git worktree prune. git worktree remove does both in one step. It also refuses to remove a folder with uncommitted changes, so you cannot lose work by accident.

8. Delete the branch

git branch -d new-branch

The lowercase -d is the safe delete. Git only deletes the branch if it has been merged. Since you just merged it, this works.

Why does the order of steps 7 and 8 matter?

Git will not delete a branch that is checked out in a worktree. Remove the worktree first, then the branch.

Simple Real-Life Analogy

Imagine a kitchen.

  • Main worktree → the main counter, where finished dishes are plated.
  • New worktree → a side counter where you try a new recipe without messing up the main one.
  • Pull → check what the other cooks added to the main counter.
  • Merge → move your finished recipe onto the main counter.
  • Push → serve it.
  • Remove + delete → clean and put away the side counter.

Useful Extras

See every worktree you have:

git worktree list

Start from the very latest remote main instead of your local copy:

git fetch
git worktree add -b new-branch ../new-branch origin/main

Clean up worktrees whose folders you already deleted by hand:

git worktree prune

Summary

  • A worktree is a second folder for the same repository.
  • Each worktree must be on a different branch.
  • Do the work in the new worktree, merge in the main one.
  • Always pull before you merge.
  • Remove the worktree before deleting its branch.
