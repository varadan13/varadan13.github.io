How Yarn Passes Arguments to a Playwright Script

Here is a command that runs one Playwright test, one step at a time:

yarn e2e e2e/regression/BUG-00003.spec.ts --debug

And here is the script it runs, from package.json:

"scripts": {
  "e2e": "playwright test"
}
“The script only says playwright test. Where do the file and --debug go?”

1. Yarn glues them onto the end

Anything you type after the script name gets added to the end of the script's command. So Yarn actually runs: 

playwright test e2e/regression/BUG-00003.spec.ts --debug

Playwright then reads two things:

  • e2e/regression/BUG-00003.spec.ts → a file filter. Only tests whose path matches it will run.
  • --debug → open a visible browser and the Playwright Inspector, then pause before the first step.

The file filter is really a pattern. BUG-00003 on its own works just as well, and regression runs every spec in that folder.

2. npm needs a --

Try the same thing with npm:

npm run e2e e2e/regression/BUG-00003.spec.ts --debug
“Why does the browser never open?”

npm reads flags such as --debug as settings for npm itself, so Playwright never sees them. Put -- in front to say “everything after this is for the script”: 

npm run e2e -- e2e/regression/BUG-00003.spec.ts --debug

Yarn 1 doesn't need the --, though it still accepts it. Older Yarn 1 versions printed a warning when you used it.

3. Other flags work the same way

# watch it run, full speed
yarn e2e BUG-00003 --headed

# record it, then replay each step
yarn e2e BUG-00003 --ui

# run only tests whose title matches
yarn e2e -g "zero override"

For what --debug, --headed and --ui each do, see How to Step Through a Playwright Test in Headed Mode.

One Trap: Start the App First

If your playwright.config.ts has no webServer section, Playwright won't start your app for you. It just opens baseURL and fails if nothing is there. Run the dev server in another terminal first: 

yarn dev

Summary

  • Yarn adds everything after the script name to the end of the script's command.
  • A path or word after playwright test filters which spec files run.
  • --debug pauses before each step so you can go through them one at a time.
  • With npm, add -- before arguments meant for the script.
  • Without a webServer in the config, start the app yourself.
